## 1. 本次交付到哪里

新增“RF / 起点专属有向弧”的候选与限制，使现有列生成能够求指定子节点的 LP。两种策略各支持普通/桶图定价；不新增搜索树、整数派车入口、车辆数分支或动态求解 CLI。

```text
测试调用者（未来为共同 BP 搜索树）
  → 列生成.solve(StageProblem, 分支上下文, options)
      → RMP：过滤初始列、求 LP、给 dual、校验新列
      → pricing：按相同限制扩展、支配、结束路线
      → 两阶段循环与受限 LP 下界检查
  ← 当前节点 LP 结果及匹配版本的路线快照
  → 分支模块.selectCandidate(快照) → 候选及流量
  → 分支模块.makeChildren(父限制, 候选) → 两份新限制
  → 调用者分别求解左右子节点
```

分支模块不拥有 Solver，不运行搜索树，也不求 LP。`StageProblem` 是只读业务数据；分支上下文是另一个值对象，不修改客户、车辆状态或动态事件。

## 3. 数据与接口

### 3.1 最小数据对象

| 类型 | 内容与语义 |
| --- | --- |
| `BranchStrategy` | `None / RyanFoster / StartDirectedArc`；None只允许空限制，不能混用策略 |
| `RfElement` | `Customer(id)`或`ExternalStart(key)`；类型标签防止同号客户/车辆混淆 |
| `DirectedArc` | `startKey`和带类型的两个端点：Source、Customer(id)、Return；不合并首尾节点 |
| `BranchDecision` | RF元素对及一起/分开，或专属弧及0/1；两种载荷用可区分的类型表示 |
| `BranchContext` | 阶段内`nodeId`、策略及累计决策的规范化值副本；阶段ID沿用外层`stageId` |
| `BranchSelection` | 阶段/节点/LP版本、候选列表和选中候选；状态为找到候选、无分数候选、数值未解决或错误 |

根节点ID为0，测试/未来搜索树给子节点分配不同ID。决策排序、精确重复去重后按内容比较，不仅靠哈希判断一致。未知ID、非法端点、混合策略属于输入错误；一组合法决策互相矛盾属于不可行子问题，不冒充解析错误。

RF端点规范化顺序；有向弧不交换方向。禁止客户自环、进入Source、离开Return及原始起点空路线的弧候选。保留相反的累计决策以表达冲突，不在规范化时将它们相互抵消。

### 3.2 公开方法与兼容性

分支头内集中四类函数：`normalizeBranches`、`routeAllowed`、`selectCandidate`、`makeChildren`。头文件只依赖动态值类型；候选接口对RMP结果/列类型使用前置声明，实现文件读取这些值类型但不链接Solver操作。

- `normalizeBranches(stage, context)`：校验并返回规范化副本，不修改调用者的数据。
- `routeAllowed(route, context)`：检查已规范化限制；基础容量、时间窗、客户合法性仍由RMP独立检查。
- `selectCandidate(stage, context, lp, columns)`：读取同版真实路线/LP值，核对Phase-II、零人工量、行覆盖及上下文；调用者先检查本节点CG已闭合。选最接近0.5的分数候选，平局按类型和原ID排序，不做strong branching。
- `makeChildren(stage, parent, selection, leftId, rightId)`：核对候选阶段/父节点来源，复制累计限制并附加本次0/1决策，不复制LP或标签。

已有接口保留；新增重载（名称沿用当前类，避免本次连带重命名）：

```cpp
DVRP_RmpController(stage, branchContext, rmpOptions);
DVRP_PricingController(stage, branchContext);
RootCgResult DVRP_RootCgController::solve(stage, branchContext, options) const;
```

旧构造/`solve(stage, options)`委托给空限制根上下文。`RootCgResult`名称暂保留，但新重载返回的是指定节点LP，不是整棵树的结果。未来树直接调用此服务，本次不新增另一套CG控制器。

RMP、pricing各持有不可变上下文副本。LP、dual、pricing结果及CG结果回传上下文；单轮日志只需节点ID，避免每轮重复复制整条历史。校验组合为`stageId + nodeId + 规范化限制 + modelRevision + phase`，pricing另核对backend。左右节点可能有相同模型版本号，不能只看版本号；旧dual不得串用。

pricing内部沿用客户`1..n`、源0、返回`n+1`；PreparedStage建立ID映射，Work构造时逐起点编译限制。车辆key始终不是客户数组下标。输出路线恢复原ID。阶段变更时调用者须清空分支历史，重建全部上下文；输入与返回值均不含悬空引用。

## 4. 从输入到输出的例子

用现有三客户分数例：容量2、客户均在距原点10的位置、需求各1、时间窗充足。两客户路线各成本20，父LP可取`[1,2]`、`[1,3]`、`[2,3]`各0.5，总成本30。

1. RF选`(客户1,客户2)`，共同覆盖流量0.5。左侧允许分别服务但不允许同路；右侧只允许两者一起或均不出现。
2. 右侧初始单客户1、2被过滤，客户3单列仍在；Phase-I通过pricing找`[1,2]`，之后Phase-II得到40。左侧完整LP也是40；父LP值30不应被当作可执行路线成本。
3. 弧策略若该父快照确为上述顺序，可选`(原始起点,1→2)`，流量0.5。左侧允许`[2,1]`，而RF“分开”不允许；它们是不同子问题，不要求两侧LP逐一相同。
4. 两种模式的`makeChildren`只生成限制；测试分别调用两次受限`solve`，得到各自快照和停止状态，不自动派车。

另例：强制外部起点K的`3→5`。该侧访问3或5的路线必须属于K，并连续按`3→5`访问；不涉及3、5的其他路线仍可用。禁止侧只禁K的这一方向，不能同时禁原始起点的`3→5`。两侧影响范围不同是覆盖等式的推论，不是偷偷增加车辆数限制。

## 5. 允许列与分支等式的等价性

以下只针对当前elementary真实路线；客户/外部起点覆盖系数`a[h,r]`均为0/1，各行右端为1。人工变量不属于真实路线。证明在精确算术中成立，实现另按第8节检查浮点误差。

### 5.1 RF

对两个元素u、v，令`b[r]=a[u,r]*a[v,r]`、`theta=sum(b[r]*lambda[r])`。由`0<=b[r]<=a[u,r]`得到`0<=theta<=1`；整数路线解中的theta只能为0或1，所以两侧不漏整数解。

- theta=0：非负性说明同时含u、v的列只能取0，等价于删除这类列。
- theta=1：`sum((a[u,r]-b[r])*lambda[r])=0`且v同理。两种差均非负，因此只含一方的列都只能取0；反过来，保留两者同现/同缺的列并满足原覆盖行就推出theta=1。

故RF无需新增分支行。多个决策的允许列取交集；外部元素是否被覆盖由`route.startKey`决定，包括外部直接返场列。

### 5.2 起点专属有向弧

令`b[r]`表示路线是否属于k且使用指定弧，`x=sum(b[r]*lambda[r])`。弧含客户时`b[r]<=该客户覆盖系数`；外部直接返场弧满足`b[r]<=外部起点覆盖系数`。因此仍有`0<=x<=1`及整数解0/1分割。

左侧删除`b[r]=1`的列。右侧使用以下局部规则，等价于原模型加`x=1`：

| 强制弧 | 允许列/扩展规则 |
| --- | --- |
| k的客户`i→j` | 含i或j的路线须属于k；i的紧邻后继必须为j，j的紧邻前驱必须为i |
| k的`Source→j` | 含j的路线须属于k且j为第一个客户；其他不含j的路线不因此被强制访问j |
| k的`i→Return` | 含i的路线须属于k且i为最后一个客户 |
| 外部k的`Source→Return` | k只允许空客户直接返场；其他起点不受此条直接限制 |

证明：对每个客户端点h均有`0<=b[r]<=a[h,r]`。`x=1`与该客户行推出`sum((a[h,r]-b[r])*lambda[r])=0`，所以含端点却不使用指定k弧的列必须取0；反过来，上述过滤使至少一个端点行恰等于x，故x=1。直接返场用外部行代替客户行。同理，这些过滤在真实LP层面也等价，不仅对整数解有效。

规则编译成逐起点的禁用弧、客户起点归属及强制前驱/后继，在扩展和返场时局部检查。左右冲突、两个强制后继或强制客户环导致没有满足条件的真实路线；首版统一让Phase-I加受限精确定价确认，不为特殊情形另写错误剪枝。

## 6. 标签与桶图怎么改

RF仍使用完整`visited`。令`rfMask`标记所有RF决策涉及的客户，起点元素在同一起点定价中是固定真/假；将RF相关访问状态表示为`visited & rfMask`，无需给每个标签重复保存一套客户状态。

| 共用方法 | RF处理 | 专属有向弧处理 |
| --- | --- | --- |
| `Work::extend` | 新访问会同时触发“分开”双方则拒绝；不把只访问“一起”一方的中间标签提前删掉 | 检查起点归属、禁弧、强制前驱/后继 |
| `Work::complete` | 所有“一起”元素的覆盖真假一致才可结束；检查外部绑定和直接返场 | 检查返场连接及强制后继；外部强制直接返场时不能扩展客户 |
| `Work::dominates` | 原条件再加两个标签的`visited & rfMask`相等 | 在满足上述局部规则的前缀之间使用原条件 |
| `Work::result`及CG/RMP入口 | 回溯后再次检查完整路线与累计限制，不用最终筛选代替搜索内约束 | 同左，弧方向、首尾端点与起点均复核 |

支配依据：同一节点、同一起点下，原规则要求A时间/载重/rc不大于B且`visited(A)`包含于`visited(B)`。任意可接在B后的未访问序列也不与A已访问集合冲突。RF再要求相关访问状态相同，则两者的后续绑定义务及互斥条件相同；更早到达可等待、更小载重仍可行、同一后缀的rc增量相同，所以A可安全替代B。

弧规则只依赖起点、当前点及下一点；已保留前缀已通过检查，相同当前点接同一后缀仍通过这些局部规则。因此该方案无需额外“已经经过哪些强制弧”的标签状态。此结论不自动推广到以后用分支行dual、不同弧过滤规则或ng的版本。

例如绑定3、5时，同在6的标签`{3,6}`和`{3,5,6}`的RF状态不同，不能用前者直接支配后者。多层RF可能削弱支配，增加标签和超时概率，这是首版已知性能风险。

桶图仍按原时间资源划分、原SCC顺序遍历，分支只减少允许扩展；原图是允许图的超集，不遗漏合法扩展。桶内和跨桶最终支配都须调用新条件；原桶最小rc用于跳过“不可能产生支配”的扫描，混合状态只可能使筛选更保守，不能直接代替状态检查。

## 7. 子节点恢复、下界与无候选

每次受限求解重新建立RMP/定价，仅保留父节点决策。`addInitialRoutes`过滤违规真实列；显式`addRoutes`若收到违规路线应报告错误，不静默吞掉后让CG空转。所有等式仍用原人工变量启动，初始列为空也可进入Phase-I；此时辅助LP可行不表示真实子节点可行。

因为不增加分支行，dual仍只有客户和外部起点两类。每条允许真实路线至少覆盖一行，人工列也覆盖一行，故全部变量总量仍不超过`m=客户数+外部起点数`。设计04的`D+m*delta`推导继续成立，但delta必须来自本节点允许路线的完整定价，Phase-I仍纳入人工列rc；固定成本、向下修正、gap与中断政策沿用[设计04第6节](04-根节点列生成文件与接口.md#6-数值下界不把-rmp-成本直接当完整-lp-下界)。

候选只统计真实路线。精确算术下，“无分数候选”的后续整数恢复依据如下；不能据此直接对浮点lambda四舍五入：

- RF：若所有元素对共同覆盖量均为0/1，任意一条正值列含u、v就使该对流量正，从而为1；于是所有含u的正值列都含v。正值列的覆盖集合只能相同或不相交，划分所有等式行；每块列权重和为1，选其中成本最小的允许路线即可获得成本不高于该LP的整数解。外部行必须包含在元素集合中。
- 弧：客户覆盖等式使每个客户在所有起点上的总入流、总出流都为1；若所有起点专属弧值整数，则每个客户只有唯一正入弧和正出弧，起点身份由逐起点流守恒一致确定。正值列只能沿这些连接形成相同或客户互不相交的完整路径，不会形成独立客户环，因为每条原列均为源到终点的elementary路径。合并相同序列后每条路径取一次；外部空路线由其专属直接返场弧确定。

未来搜索树可据此恢复整数见证，复核覆盖、资源、分支和成本，再结合有效下界判断节点完成。本次候选接口仅返回`NoFractionalCandidate`及诊断，不实现生产整数恢复，不把它当作`IntegerOptimal`；这符合已确认需求的“未完成恢复时报告未解决”。小实例测试必须覆盖该边界。

流量按原值累计，不先逐项舍入lambda；使用显式整性容差识别候选，越界/覆盖残差超标归数值未解决。状态近似整数不等于上述精确证明的前提成立。任何中断快照仍只用于诊断，不能因有候选或没有候选替代定价闭合证据。

## 8. 独立验证与构建边界

新增默认关闭的`DVRP_BUILD_BRANCHING_TESTS`（无solver语义/定价）和`DVRP_BUILD_BRANCHING_CG_TESTS`（CPLEX受限CG）。现有使用RMP/pricing的目标需包含分支实现，不能只让新增测试链接成功；默认reader构建仍不要求CPLEX。

无solver测试复用小实例全集枚举入口，但由测试独立计算RF共同覆盖、弧系数和允许后缀，不调用生产`routeAllowed`生成答案。枚举基准仍遵守原5客户/5外部起点保护上限；生产模块无该规模限制。

CPLEX对照在新测试cpp内部，用全集真实列及显式RF/弧0或1等式建立完整LP/MIP，不用生产列过滤或RMP建模函数生成标准答案。此模型可能有额外行，其dual不直接喂给生产pricing；只比较子节点目标/可行性，定价最小rc另在相同生产dual下与枚举比较。

必验矩阵：两种策略×两版pricing×Phase-I/II；客户/外部元素、首尾弧/空路线、深层限制与冲突、无可行后缀、零需求/零距离、非连续ID、微小分数、版本串用、预算中断和空限制回归。RF和弧须分别有小实例整数方案左右分割检查；比较父MIP与两子MIP最优值的最小值，不能要求父LP等于子LP的最小值。

分别统计两版标签数量和耗时，但只有固定同一节点限制时才比较最小rc/LP值；不同分支策略形成的子节点不必同值。正式整数BP对照、全局树时限和动态总距离对照不在本轮。

实际验证命令、计数及限制统一见模块说明，不在此重复维护。已有R204静态风险继续保留。需求已合并到实现说明，详细导读已提供。
