> 状态：已完成（保留稳定接口与接入边界）
>
> 最后更新：2026-10-26
>
> 需求已完成并合并进[模块说明](../../实现说明/DVRP动态BP闭环与命令行模块.md)，实际方法见[导读](../../实现说明/DVRP动态BP闭环流程与方法导读.md)。先读第1—4节理解边界；本文不维护第二套测试结果。

## 1. 只补上调用者，不重写算法

reader、动态状态机和单阶段BP通过新增 `simulation` 模块串联；新 `dvrp_solve` 负责命令行。旧 `dvrp` 继续只读摘要，不需要修改已有动态状态机或优化算法。

```text
solve_main：解析参数 → 原reader → 构造DynamicController
  → SimulationController.run
      → dynamic.buildStageProblem：生成StageProblem值快照
      → BP.solve：每阶段新建树、RMP、pricing
      → toStageSolution：BpResult转换成StageSolution
      → dynamic.acceptSolution：重验路线和接续车辆
      → 下一事件advanceTo / 最后finish
  ← SimulationResult：完成或停止、阶段记录、实际累计距离
```

动态层只输出 `StageProblem`，不会直接操作根节点、标签或solver。BP已负责内部编号和模型转换，这次不再转换一份数据。`StageSolution`只含路线和状态，车辆轨迹仍由动态层计算。

## 3. 接口和所有权

### 3.1 调用者只需一个运行入口

```cpp
// 已实现接口；声明集中在simulation_controller.hpp。
SimulationResult DVRP_SimulationController::run(
    DynamicController dynamic,
    const BpOptions& options,
    std::ostream* log = nullptr) const;
```

输入是由原reader数据构造、尚未处理首阶段的动态控制器，以及已有 `BpOptions`。按值接收控制器，CLI可移动交入；run拥有整个仿真状态，不持有外部可变引用。首版拒绝中途恢复状态，不实现断点续算。

`BpOptions`已有策略、后端、阶段秒数和节点上限，不再复制一套同义配置。配置在整次run内不变，预算在每次 `BP.solve` 重新起算。子组件仍取自己的上限与上层剩余预算的较小值，所有配置上限在运行头中输出。

`SimulationResult`集中保存运行状态、最终有效 `DynamicState`、动态 `StageRecord`、按stageId对应的BP摘要、耗时和原因。摘要包含状态、见证路线/成本、界/gap、节点/定价/标签统计；停止阶段另保留快照和详细BP诊断。不跨所有成功阶段保存完整BP节点迭代日志，更不持有Solver、树或标签池。

运行状态复用 `SimulationStatus`。若外层校验或输出失败，运行结果为 `StoppedError`；`finalState`可保留失败前仍为Running的最后有效快照，不修改私有状态来伪造一次推进。完成与否以运行结果为准，输出同时标明停止原因和最后结算时间。

### 3.2 测试只替换单次求解调用

同一头文件的内部测试区提供 `SimulationDetail::runWithSolver`，接收类型为 `std::function<BpResult(const StageProblem&, const BpOptions&)>` 的回调；run只是给它传入真实 `DVRP_BpController::solve`，两者共用同一个事件循环。

这条接缝用于确定性制造“第二阶段超时但有见证”、陈旧stageId或损坏成本，并在调用时核对快照。不是插件系统；CLI不能选择假求解器，生产也不链接MIP对照。真实BP用例和故障注入用例分别记录，不能把后者说成实际观察到solver超时。

日志流是可选、同步借用的输出端；run不关闭它，也不在返回后保留引用。`nullptr`用于只消费结构化返回值的测试，不需要文件系统。

## 4. 事件循环的固定顺序

1. 从dynamic取得当前stage和下一事件时间；先输出阶段输入，使长时间求解时能看见当前在做什么。传给BP的只有该快照，不能传完整未来客户表。
2. 调用真实BP并核对stageId、策略、后端。BP内部每次从新根开始，不继承旧阶段模型、列或分支历史。
3. 用已有 `toStageSolution` 转换。仅 `BpStatus::Optimal` 且转换成功可进入接收；其余状态按动态层已有停止通道记录，并保留原BP状态/见证，不再推进。
4. 在动态控制器的临时值副本上调用 `acceptSolution`；核对新记录的路线成本和总计划成本与BP见证一致。沿用整数恢复的有限值及 `TOLERANCE * max(1, |a|, |b|)` 成本核对口径，最优gap仍由BP自己的标准判断。
5. 校验和本步骤输出成功后才提交该副本，避免新加的成本核对失败时已经替换计划。`advanceTo/finish`同样先在临时副本完成，成功才提交；异常保留上一个有效状态，不重算一套动态轨迹。
6. 有下一事件就调用 `advanceTo(nextTime)`，输出实际距离增量，然后重复；否则调用 `finish()`，检查Completed后汇总。现实求解秒数只计计算预算，不推动仿真时间。

对于合法的非Optimal结果，即使含可行见证也不执行；对于错误身份、转换异常或非法路线，只记录诊断，不能把异常改写成不可行。停止后不再调用下一阶段求解，不调用 `advanceTo/finish` 兜底。

例如：Q=100，车场x=0；客户1在x=10、需求10、服务20、时刻0披露，客户2/3在x=12/14、需求各10、服务0、时刻5/15披露，时间窗充足。

| 时刻 | 上层传给BP的信息 | 动态层保留什么 |
| --- | --- | --- |
| 0 | 客户1、原始起点 | 接受原始路线，分配车辆1 |
| 5 | 客户2；外部key=1，位于客户1、出发时间30、剩余容量90 | 车辆仍前往客户1，已走5；固定剩余行驶5 |
| 15 | 客户2、3；相同外部key=1、时间30、剩余容量90 | 车辆仍服务客户1；客户2从旧方案释放重排，累计实际10 |
| 最终 | 无下一披露事件，不再求新阶段 | finish完成客户2/3及返场，实际总距离28 |

这里的阶段计划值不能相加；28来自动态轨迹的实际结算。这是明确的手算例，不推断一般动态实例四组合最终距离必然相等。

## 5. CLI、输出与退出码

新入口只接受一个文件和以下选项，未知、重复、缺值、非有限秒数或非整数节点数均报参数错误：

| 参数 | 语义 |
| --- | --- |
| `--branching rf\|arc` | 必填；RF或起点专属有向弧 |
| `--pricing plain\|bucket` | 必填；普通标签或前向桶图 |
| `--stage-seconds N` | 默认60，有限且非负；0用于确定性预算边界 |
| `--max-nodes N` | 默认10000，非负整数；计实际启动的节点CG，0也合法 |
| `--help` | 独立使用，输出用法后返回0，不读取文件或初始化solver |

main先解析求解选项，再构造仅含“程序名、文件路径”的argc/argv视图传给原reader，不把求解参数交给reader。reader仍负责内容校验、实例名和八字段；车辆数只报告。输入失败沿用reader退出机制，不要求此时有仿真结果。

文本用固定记录前缀和 `key=value` 字段：`RUN`（配置）、`STAGE`（输入）、`START`/`ROUTE`（起点/路线）、`SOLVE`（状态/界/统计）、`ADVANCE`（实际距离）、`SUMMARY`（完成或部分结果）；字符串引用/转义，数值保留足够精度，缺失值用 `NA` 而非0。失败候选明确 `executed=false`，不打印为执行路线。

日志逐阶段刷新并检查流状态；输出失败返回非0、尽力写stderr，不再继续仿真。阶段已接受和区间已行驶分别记录；最终完成摘要只在finish成功后生成。结果中 `seconds` 表示仿真调用耗时，CLI可另报含读取的总耗时，不与currentTime混淆。

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部Completed，或帮助正常输出 |
| 1 | 输入内容/文件错误，校验、数值未解决、日志或其他运行错误 |
| 2 | 命令行参数错误 |
| 3 | 已证明当前阶段不可行 |
| 4 | 算法超时，无论是否有整数见证 |
| 5 | 节点、标签/图资源或迭代预算耗尽 |

退出码用于脚本粗分类，细因以原BP状态和错误信息为准；不要用1表示“已经证明不可行”。

## 6. CMake接入边界

新增默认OFF的 `DVRP_BUILD_SOLVER`（生产dvrp_solve）及 `DVRP_BUILD_SIMULATION_TESTS`（接入测试）。后者要求BUILD_TESTING，前者不要求；测试选项可为CLI测试同时构建dvrp_solve，但生产目标绝不包含test源码。

把现有CMake中CPLEX查找和目标配置与“要求BUILD_TESTING”的检查分开：商业solver按生产/solver测试需求启用；测试开关仍单独检查。生产配置不带 `test/stage_reference` 头路径，只有测试目标链接枚举/MIP对照。保留当前CPLEX DLL复制及平台链接规则。

复用同一生产源码列表编译CLI与新测试，不新建library；`ROUTEOPT_SOLVER=CPLEX`显式选择后端，其他后端首期明确拒绝。全部新旧可选开关关闭时，不查找CPLEX，reader及原25项测试保持不变。

## 7. 验证边界

测试覆盖循环、真实BP、独立MIP核对和CLI；不改标签或状态算法。完整结果与复现命令统一见模块说明。

- 真BP四组合驱动三事件例，逐次核对承诺、外部时间/容量、实际距离及最后返场；补空初始阶段、同刻完成、固定返场和无客户外部返场。
- 从实际出现的同一小阶段快照重跑四组合，与独立完整MIP比较成本/可行性；保持对照器5客户/5外部上限，不把MIP结果供给生产BP，也不要求一般动态运行最终距离一致。
- 注入中间阶段不可行、超时有/无解、节点/资源/迭代限制、数值错误、错误stageId/策略/成本、非法路线和输出失败，检查最后有效状态及后续调用次数为0；另用真实零时限/零节点预算，以及第二阶段树的早/中/晚预算验证实际停止与保留见证。逐个节点预算的穷尽测试仍由已有BP模块负责。
- CLI脚本检查四组合完整TXT、帮助、参数/文件/内容错误、不可行和预算退出码，以及不能偷偷截取客户。外部测试超时只作harness保护，不冒充生产求解状态。
- Release/Debug跑新增和既有回归；新生产开关ON且BUILD_TESTING=OFF单独构建；全选项OFF保留无solver测试。按约定检查原版源码差异及不带-u的C204/R204，历史未完成风险独立报告。

真实较大TXT只做限时冒烟；需要缩减时另存明确命名的fixture并记录来源，不修改生产实例。正确性闭环与性能承诺分开。
