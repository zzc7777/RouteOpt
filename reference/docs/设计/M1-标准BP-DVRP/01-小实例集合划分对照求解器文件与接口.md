## 1. 边界与调用链

这是测试用的完整路线 LP/MIP 求解器，不是生产 BP，不接根节点、标签或搜索树。CPLEX 求整数模型时内部会做自己的搜索，不等于已经实现 RouteOpt BP。

```text
测试驱动 → DynamicController.buildStageProblem()
              ↓ StageProblem 值快照
         enumerateStage(stage)
              ↓ EnumeratedStage：阶段副本 + 全部可行路线
              ├─ computeReducedCosts(duals) → pricing 的对照数据
              ├─ solveFullLp(options)      → LP 值、lambda、dual
              └─ solveFullMip(options)     → 整数路线与 StageSolution
                                               ↓
                        DynamicController.acceptSolution()
                             → 下一事件 / finish()
```

LP 和 reduced-cost 检查是旁路，不驱动车辆。动态模块仍独立重算时间轨迹与成本。生产 `main.cpp` 不接入这条测试链。

## 3. 公开接口与数据所有权

位于 `RouteOpt::Application::DVRP::Testing`：

```cpp
EnumeratedStage enumerateStage(const StageProblem& stage);
LpReferenceResult solveFullLp(const EnumeratedStage& all, const ReferenceOptions& options);
MipReferenceResult solveFullMip(const EnumeratedStage& all, const ReferenceOptions& options);
std::vector<double> computeReducedCosts(const EnumeratedStage& all, const StageDuals& duals);
```

| 类型 | 最少需要保存的信息 |
| --- | --- |
| `EnumeratedRoute` | 现有 `StageRoute`、真实 `cost`；客户顺序不含起点和返回节点 |
| `EnumeratedStage` | 输入阶段值副本、全部路线；只由完整枚举成功后构造，提供只读访问 |
| `StageDuals` | 按原客户ID索引的客户dual、按外部startKey索引的起点dual；无原始起点dual |
| `ReferenceOptions` | 单次LP或MIP优化时间上限（默认60秒）；不含已知最优值 |
| `LpReferenceResult` | 独立LP状态、可选路线目标值、lambda、最优时的dual、原始solver状态、耗时和消息 |
| `MipReferenceResult` | 现有 `StageSolution`、有整数解时的可选路线目标值、可用的最优界、原始solver状态、耗时 |

LP状态只区分最优、不可行、超时和错误，不把LP可行点当作可执行整数路线。未获得有效目标或dual时使用空值，不用0冒充结果。

`EnumeratedStage` 内部拥有快照，LP/MIP只读取它，不再次接受另一份可能不一致的阶段参数。枚举中断或错误抛出带原因的异常，不返回“半个全集”；非法输入与规模超限不能变成 `Infeasible`。

每次求解拥有独立的model/env并在退出时释放（包括异常）；不把指针交给动态层，不跨阶段共享模型，也不浅拷贝拥有资源的 `Solver`。结果为值对象，不扩充现有 `StageSolution`。

## 4. 枚举、编号与模型转换

### 4.1 路线全集

按起点依次枚举0至n个客户的所有不重复序列；原始起点跳过空序列。按起点时间传播到达、等待、服务完成和返场；只保留容量、时间窗及H均满足的序列。

内部使用连续下标和访问集合；输出恢复原客户ID。只读 `StageProblem` 提供的坐标、时间和容量，外部位置无需再次在阶段客户表中查到。车辆key与客户ID属于不同命名空间。

弧成本/时间调用已有 `routeOptDistance`，可行性使用动态模块相同容差。枚举独立实现资源传播，不调用未来 pricing 的标签或剪枝代码，以免两边共享同一错误。

首版小规模下直接检查所有序列，不按“当前前缀直接返场不可行”剪掉全部延伸；截断后的距离不应未经证明就假设严格满足三角不等式。同一集合不同顺序全部保留，供以后检查弧分支；不按成本支配删列。

### 4.2 完整LP与MIP

- 客户行：按客户ID建立 `=1`；外部起点行：按startKey建立 `=1`；没有原始车场车辆数行。
- 路线列：每个访问客户系数1，所属外部起点行系数1，目标系数为真实路线成本。
- LP设 `lambda >= 0`，不额外设显式上界1；每列至少属于一个上述等式，已隐含不超过1，避免冗余上界dual干扰定价核对。
- MIP显式设二元类型及 `[0,1]`；使用独立模型，不把MIP求解后的dual当成LP dual。
- 不创建人工列或Phase-I；全集仍不能覆盖时，完整模型可以真正不可行。零客户/零起点返回空最优方案；缺列的必选行不省略。
- `fixedCostAfterTau` 不进入列成本，报告时加一次。行号、列号与客户ID、startKey、路线索引分别保存映射。

源代码核对提醒：原 `Solver::addVars` 的 CPLEX 实现调用 `CPXaddcols`，没有使用传入的 `vtype`；本实现须明确调用 `setVTypeArray`（或等效显式设类型入口），并通过模型类型和整数性测试核验。

### 4.3 reduced cost 的对照接口

原始路线：`cost - sum(customer dual)`；外部路线还减去其起点dual。要求dual的键恰好对应当前客户和外部起点，返回顺序与路线全集一致。

既接受完整LP的dual，也接受人工构造或未来RMP提供的同模型dual。当前不支持分支行dual，不决定未来分支用q还是x。LP最优时检查原始/对偶目标、列reduced cost及互补性；对偶解不唯一，不要求不同求解过程的dual逐项相等。

## 5. 一个输入到输出的例子

使用实现说明中的时间100、外部key42及客户5/8的例子。原始起点key0、返回节点及客户ID均语义独立；外部起点位于已承诺客户3，不把3再次覆盖。

| 候选路线 | 客户5行 | 客户8行 | 外部42行 | 成本 |
| --- | --- | --- | --- | --- |
| key42 → 5 → 8 → 返回 | 1 | 1 | 1 | 18 |
| key42 → 返回 | 0 | 0 | 1 | 10 |
| key0 → 5 → 8 → 返回 | 1 | 1 | 0 | 28 |

这只是全集中的3列，不是全部模型。可返回 `StageRoute{42, {5,8}}`，路线成本18、加固定7后目标25，130出发、148返场。反向客户顺序也可能同为最优，不要求CPLEX固定选择同一顺序。

已有真实控制器生成阶段时，测试把 `result.solution` 交给 `acceptSolution` 重验；上述人工key42快照用于独立阶段测试，不能直接提交给没有该车辆的控制器。

## 6. CPLEX接入、状态和构建边界

- `DVRP_BUILD_REFERENCE_SOLVER=OFF` 为默认值；关闭时不查找或链接CPLEX，保留原25项测试。开启时要求 `BUILD_TESTING=ON`。
- 开启后使用CMake `ROUTEOPT_SOLVER=CPLEX` 选择后端；首版其它值明确拒绝，不回落为别的后端。CPLEX安装位置用 `CPLEX_ROOT`，不硬编码个人路径。
- 只给新测试目标设置 `SOLVER_TYPE=1`、DVRP solver头文件/源文件和CPLEX链接依赖；不混用原 `packages/` 的同名源码，不引入cuts、HGS、XGBoost等。
- 使用已有 `newModel/addConstraints/addVars`、`optimize/mipOptimize`、`getX/getDual/getObjVal/getStatus` 等接口；必要状态/最优界、绝对gap设置在DVRP接口副本中补齐，不另写一套CPLEX建模框架。
- 明确区分API调用返回码、LP终止状态和MIP终止状态；不能用仅映射LP的 `SOLVER_OPTIMAL` 判定MIP。外层检查返回码并转换为诊断，不直接用会 `exit` 的 `SAFE_SOLVER` 跳过资源释放和记录。
- 单线程；相对与绝对MIP gap设为0，记录数值容差及最优界；浮点solver的最优结论不是精确有理数证明。不能把数值失败或尚未闭合的界差当作最优。
- 时间上限作用于每次优化调用，分别记录枚举和求解耗时，不冒称整个仿真的总时限。超时按有无整数incumbent映射已有状态，动态层一律停止；只有可用解才读取目标和路线。

构建方式（CPLEX路径按本机配置传入；实测命令和结果统一见模块说明）：

```powershell
cmake -S packages_dvrp/application/dvrp -B build/dvrp-reference -DDVRP_BUILD_REFERENCE_SOLVER=ON -DROUTEOPT_SOLVER=CPLEX -DCPLEX_ROOT="<CPLEX安装根目录>"
cmake --build build/dvrp-reference --config Release -j 8
ctest --test-dir build/dvrp-reference -C Release --output-on-failure
```

## 7. 已实现的验证边界

1. 枚举及映射：手列9条路线、0/5/超限规模、非连续客户ID/车辆key、同位置起点和输入不变；保留全部可行顺序。
2. solver副本与完整LP：小矩阵逐项核验系数/成本、无车队行；与手算值比较，检查对偶目标和reduced cost。
3. 整数MIP：核验二元类型、整数最优值、覆盖/起点等式、空阶段和不可行；用独立人工小矩阵验证LP/MIP差异，不能只测试恰好整数的LP。
4. 状态与资源：测试LP/MIP原始状态转换、模拟超时有无解、实际API参数错误、重复独立调用；未注入许可失败或进行专用泄漏检测。真实时限冒烟与确定性状态测试分别记录，不依赖“必在极小时间内超时”的不稳定断言。
5. 动态接入：仅测试驱动枚举+MIP循环，成功方案由动态层重验；失败/超时停止。运行Release/Debug及原有25项测试；不把已有原版R204风险说成已修复。
