## 1. 放在哪里、谁调用谁

路径均相对 `packages_dvrp/application/dvrp/`。新增 `src/column_generation`，集中管理列生成控制，不放进动态层，也不把 pricing 改成求解总入口。

```text
测试入口（未来为阶段 BP）
  → DVRP_RootCgController.solve(StageProblem, options)
      ├─ DVRP_RmpController：持有 LP、解 LP、给 dual、加列
      ├─ DVRP_PricingController：逐起点找最小 rc 和负列
      └─ 根控制器：循环、Phase 切换、总预算、结束判断
  ← RootCgResult：LP 快照、数值界、日志、停止状态
```

这是无分支根问题的求解服务，不是搜索树节点。下一步分支树需要另行设计节点、分支限制和子节点可行性恢复，不能仅复用本接口就声称已支持子节点。

## 3. 输入输出与所有权

公开入口为 `RootCgResult DVRP_RootCgController::solve(const StageProblem&, const RootCgOptions&) const`。控制器本身不缓存阶段；每次调用在局部创建一份RMP和一份pricing，调用结束释放solver。两者各自复制阶段，不另加第三套基础数据模型。

| 类型 | 主要内容及约束 |
| --- | --- |
| `RootCgOptions` | 总时限、最大 LP 迭代数、`RmpOptions`、`PricingOptions`、是否生成初始列、LP 差距容差；通过构造参数显式选择 backend |
| `RootCgBound` | 对应阶段/版本/Phase、对偶和、最小 rc 修正、舍入余量、保守下界、当前 RMP 目标及差距；不能单凭它证明整数最优 |
| `RootCgSnapshot` | 同一次有效 `RmpLpResult` 与当时的 `RmpColumn` 值副本、可选数值界；`lambda[id]` 始终对应该快照的列 ID |
| `RootCgIteration` | 轮次、Phase/版本、人工量或目标、新增/总列数、有效最小 rc、耗时及本轮动作；不复制每轮全部路线/标签 |
| `RootCgResult` | 阶段、backend、停止状态、可选最后有效快照、逐轮记录、总耗时和诊断；无效数值用空值，不填零 |

默认总时限60秒、最多10000次LP求解、生成初始列；每轮LP/price上限取现有单次上限与总剩余时间的较小值。容差和资源限制可配置，输入必须有限且合法，不能用负值代表无限；最大迭代数0表示不启动LP。

输出不含 solver 指针、标签或对局部对象的引用；控制器析构后仍可读取结果。`RmpColumn.lpColumn` 只作为当时列号记录，不能用它操作已释放的模型。中断前的快照保留原版本；不得拼接“旧 lambda＋新列池”。

状态为 `LpConverged / LpInfeasible / TimeLimit / ResourceLimit / IterationLimit / NumericalUnresolved / Error`。只在前两种状态满足对应证据时作结论；其余状态的快照仅用于诊断，不触发动态执行或BP剪枝。入口将非法输入及一般组件异常转换为Error，传播到入口的内存分配失败归ResourceLimit，数值界无法建立归NumericalUnresolved；无有效快照时保持空值。

## 4. 一个具体输入到输出的例子

沿用现有分数测试：原始车场在 `(0,0)`、容量 2，三个客户都在 `(10,0)`、需求各 1，时间窗足够宽，没有外部起点，固定成本设为 0。

1. 初始三条单客户路线各成本 20，RMP 可行路线成本为 60。
2. pricing 找到可行双客户路线，控制器加列并重新求 LP。
3. 最后可得到三条分别覆盖 `{1,2}`、`{1,3}`、`{2,3}` 的路线，各取 `lambda=0.5`，路线成本 30；通过定价及数值界核对后返回 `LpConverged`。
4. 这不是三辆“半辆车”的执行方案；整数最优为 40。本模块返回 LP 数据，不创建可执行 `StageSolution`。

输入的原客户 ID、`startKey` 原样传给现有 RMP/pricing。连续编号转换仍在各模块内部，输出恢复原 ID；根控制器无需建立另一张图或把车辆 key 转成客户下标。

## 5. 每轮执行与最小接口扩展

1. `solve` 一开始记录总时钟；校验选项、建立两组件、按配置加初始列，步骤前后检查剩余时间。
2. 用剩余时间调用 RMP；只有 `OptimalRmp` 且结果完整才继续，立即保存与列池匹配的有效快照。
3. 若 Phase-I 人工量不超过现有 `TOLERANCE`，调用 `enterCostPhase()`，下一轮重新求 LP。不能用 Phase-I dual 做 Phase-II 定价。
4. 否则用当前 dual 和剩余预算定价；中断直接传播停止状态。完整结果检查阶段、版本、Phase、backend、起点唯一性、见证与候选一致性。
5. 重算候选 rc，交 RMP 独立校验并加列；核对新增列数及成本。全是重复负列或数据不一致则 `Error`，不空转。
6. 没有候选时按第 6 节计算数值界：证据充分才收敛/判不可行，否则 `NumericalUnresolved`。不自动放宽阈值、切换 backend 或重写 pricing。
7. 目标未下降、已有整数 lambda 都不是提前停止依据；循环上限不依赖路线全集大小。

RMP 新增 `RmpLpResult solveLp(double timeLimitSeconds)`；无参版本继续使用构造时的默认时限，并在每次调用重新设置。显式时限只作用于本次求解，不改变默认选项、行列或模型版本；仍沿用原结果清理和错误处理。根控制器不直接操作 `Solver`。

总时限包括组件构造/预处理、初始列、LP、定价、复核及结果整理；对不可中断的构造/solver API，在返回后检查，不承诺硬截止。已超总时限时不再启动下一操作，也不把刚返回的结果报告为按时完成。标签/图数量限制继续交 pricing；内存分配失败归资源不足，不等同于已测量进程内存上限。

## 6. 数值下界：不把 RMP 成本直接当完整 LP 下界

### 6.1 精确算术下的依据

设共有 `m = 客户数 + 外部起点数` 个右端为 1 的等式行，对偶向量为 `y`，`D = sum(y)`。每条真实路线至少覆盖一行（原始路线含客户，外部空路线也覆盖外部行）；每个人工变量恰好覆盖一行。因此任一可行解的全部非负变量总量不超过 `m`。

对当前 Phase，把所有允许真实路线的最小 reduced cost 记为 `rho`，由全部起点完整定价取得。若一个起点无可行路线，就没有该起点的最小值，不用 0 伪造；若所有起点都无路线，则真实路线部分不参加取最小。

```text
Phase-II：delta = min(0, 所有有效逐起点最小 rc)
Phase-I ：delta = min(0, 所有有效逐起点最小 rc, 各行人工列的 1-y[h])
完整 LP 下界 L = D + m * delta
```

证明：把真实变量和仍可用的人工变量统一记为 `z`，则目标 `c·z = D + sum(rc[j]*z[j])`。由于各 rc 不小于 `delta <= 0`，且 `sum(z) <= m`，所以 `c·z >= D + delta*sum(z) >= D + delta*m`。Phase-II 固定为零的人工列不参加取最小。空模型 `m=0` 单独返回解析零路线成本。

Phase-I 的 `L>0` 说明最少人工量仍大于零，真实路线 LP 不可行；Phase-II 可行 RMP 成本 `U` 与 `L` 夹住完整 LP 最优值。这里没有新增车辆数量约束，`m` 只是由现有等式推出的保守变量总量界；加入分支/cuts 后不能未经证明继续套用。

### 6.2 浮点实现与终止

- `D` 从有效 dual 累加，不直接替换成 RMP 目标；Phase-I 同时检查人工列 rc。使用保守累加和向下修正，舍入余量随数值规模计算并记录；不假定 MSVC 的 `long double` 一定比 `double` 精确。
- 将计算的最小 rc 向下留余量，再得到 `L_safe`；必要的求和舍入余量也向下扣除。校验非有限值、异常的上下界反转及目标/dual 不一致，不能靠截断差距为零隐藏错误。该数值界依赖现有浮点定价正确性和容差口径，不称为区间算术或有理数证书。
- Phase-II 只在完整定价且无待加负列时，检查 `U-L_safe <= absTol + relTol*max(1,abs(U))`；建议默认 `absTol=1e-6`、`relTol=1e-8`，输出实际差距。
- Phase-I 人工量仍大于 `1e-6` 时，只有完整定价支持 `L_safe>1e-6` 才报告 `LpInfeasible`；无候选但下界不能排除零时报告 `NumericalUnresolved`。
- 例如 200 行、最小 rc 为 `-5e-6` 时，虽不满足现有加列阈值 `rc<-1e-5`，下界仍须至少扣除 `0.001`，再计舍入余量，不能直接把 `D` 报为下界。首次实现保留当前候选阈值；不足以闭合就如实未完成。
- 固定成本只在 Phase-II 同时加到上下界及阶段计划成本中一次，不改变差距；人工量下界不能标作距离下界。舍入策略的边界测试是交付条件，不能调大容差只为通过测试。

## 7. 独立测试与构建隔离

新增 `DVRP_BUILD_ROOT_CG_TESTS`，默认 OFF；开启时要求 `BUILD_TESTING=ON` 并使用已有 CPLEX 配置。不强制打开其他测试开关，不新增 reader CLI 参数；新测试目标直接编译根控制器、RMP、两版 pricing、动态距离实现及 solver 副本。

同一测试目标可链接现有小实例对照器，但其用途仅是独立审核；生产根控制器不能包含测试头、调用枚举或读取 MIP 答案。旧 pricing 接线测试保留，新增测试调用正式入口，不能只继续验证旧的测试循环。

| 测试层 | 必须验证 |
| --- | --- |
| 正式循环接线 | 手算、固定种子多起点阶段、两版 backend 分别与完整 LP 比较；含缺初始列、Phase 切换、空阶段、固定成本及 LP30/MIP40 |
| 下界 | 独立遍历小实例全部列，验证修正覆盖所有 rc，`L_safe` 不高于完整 LP 最优值；人工列 rc、负列阈值附近和规模放大不能假收敛/假不可行 |
| 上下文与异常 | 错版本/Phase/起点、重复候选、无新增列、非有限数值、超时及迭代/标签预算；结果快照与列 ID 配对 |
| 生命周期/兼容性 | 连续解不同阶段，输入不被修改；新时限重载及旧无参调用；默认无 CPLEX 构建不回退 |

确定性异常测试采用与现有 `RmpDetail` 相同的窄方式：在根 cpp 内集中 `RootCgDetail` 的纯校验/分类函数，测试 cpp 前向声明后直接检验；这些函数必须被正式循环调用。不增加可替换 solver 的公共框架，不为测试修改生产数据，不把分类测试冒充真实 solver 超时。实际预算中断另做入口测试。

Release/Debug 跑新增测试与现有回归；构建命令、结果和故障覆盖在实现交付时记录。原静态 C204/R204 按现有约定执行并诚实保留风险，不修改原算法。
