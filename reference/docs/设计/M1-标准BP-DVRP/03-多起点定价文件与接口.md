## 1. 边界：同一个接口，两种标签处理方法

~~~text
DynamicController → StageProblem                          已实现
                          ↓ 同一快照
生产根列生成控制器 / 测试驱动                              见设计04
  ├─ RMP.solveLp() → RmpDuals                              已实现
  ├─ Pricing.price(duals, options)
  │     ├─ PlainLabeling：普通队列，不建桶图                 已实现
  │     └─ BucketGraph：桶弧＋SCC＋桶内/跨桶支配              已实现
  └─ 检查完成状态/版本/rc → RMP.addRoutes(StageRoute)         复用已有加列
~~~

两版共享阶段数据、资源传播、支配判据、rc计算和路线回溯，**不共享标签调度循环**。这让差异集中在桶图方法本身；不能拿“普通版elementary、桶图版ng”作同问题对照。Pricing不是数据对象或BbNode，不持有Solver指针，不推进动态事件。

## 3. 算法依据与复制边界

## 4. 公开接口、结果与所有权

公开 DVRP_PricingController(stage) 和 price(const RmpDuals&, const PricingOptions&)，命名空间沿用 RouteOpt::Application::DVRP。构造复制阶段，调用方不需延长输入寿命；每次price重置标签、dual、候选与成本界。跨阶段重建，内部不使用可变全局状态。

| 类型 | 契约 |
| --- | --- |
| PricingBackend | PlainLabeling / BucketGraph；调用方显式选择，不静默切换 |
| PricingOptions | backend、整轮起点共享时限、保留标签上限；BucketGraph另有bucketCount与图规模上限 |
| PricedRoute | StageRoute＋真实cost＋本轮reducedCost |
| StartPricingResult | startKey、是否有可行路线、可选最小rc及见证路线；最小值只在完整搜索后有效 |
| PricingResult | stageId/modelRevision/phase/backend、Complete/TimeLimit/ResourceLimit/Error、逐起点结果、负列候选、统计/诊断 |

实际默认整轮price时限60秒，每起点20万保留标签、25个bin、10万桶节点、500万后继/依赖邻接条目；均可配置。图预算按构建条目保守计数，包括正反依赖邻接，不等于存活弧数。预算覆盖本轮起点准备、建图、SCC、扩展及回溯；构造函数的阶段复制和客户距离预处理另计。标签/图数量上限不等于进程内存字节上限，不承诺适用100客户。

校验阶段、客户与起点、dual键集合/有限性/Phase。等式dual允许为负；modelRevision原样带回，pricing无法自行知道RMP最新版本，调用方必须传当前OptimalRmp.duals并在加列前核对来源、阶段、版本及Phase。

每起点完整搜索后最多返回一条最负候选；无可行路线用空值，不用0代替最小rc。Complete不等于无负列；预算中断或数值错误时清空整轮starts/candidates，不输出全局最小值证明。标签用稳定下标作前驱，被支配只标记失效，不能破坏后继回溯；标签预算按实际保留对象计。

## 5. 共用的编号、资源和rc

内部当前源S=0、客户1..n、返回D=n+1；维护原ID↔连续编号，startKey独立保存。每个起点单独搜索，客户矩阵共用，首弧按起点计算。外部位置客户不再加入访问序列。

允许S→客户、不同客户之间、客户→D；仅外部允许S→D。D只入不出，禁止自环、回到S或经过其它外部起点。空客户阶段仍处理外部直接返场。原始路线至少一位客户。

Label保存末端、服务完成时间t、本段已用容量q、rc、真实成本、完整visited及前驱。源t=startTime、q=0，不重复扣承诺客户资源。进入客户j：

~~~text
arrival = t + travel[i,j]
begin   = max(arrival, ready[j])
t_new   = begin + service[j]
q_new   = q + demand[j]
检查 begin <= due[j] + tolerance，q_new <= remainingCapacity + tolerance
~~~

到D检查t+travel[i,D]不超过H；完成失败不阻止继续访问其他客户。距离采用routeOptDistance；时间保持double及现有容差，不强制落在RESOURCE_FACTOR=100网格。visited使用已有routeOptLong，只标客户位，n < MAX_NUM_CUSTOMERS，不引入5客户上限。

设w=0（Phase-I）或1（Phase-II），pi为客户dual、mu为外部dual：

~~~text
原始路线 rc = w × cost − Σ pi[i]
外部路线 rc = w × cost − Σ pi[i] − mu[startKey]
~~~

源rc为0或−mu[k]；到客户j加w*c[i,j]−pi[j]，到D加w*c[i,D]。fixedCostAfterTau不参与；旅行时间不乘w。用RC_TOLERANCE=-1e-5判断负列，可行性沿用TOLERANCE=1e-6，最终路线独立重算核对。

## 6. 共用支配判据，普通版如何运行

同起点、同末端，若A的time/load/rc均不大于B，且visited(A)为visited(B)子集，则A可替代B。B的任一合法后缀对A也合法：没有新重复客户、容量不更紧、时间传播不更晚，后缀rc增量相同。本论证限当前无RF/cuts约束的模型；支配使用保守比较，不把略差反复当作不劣。

普通版维护每个末端节点的非支配标签集和待扩展队列。新标签与该节点全部有效标签比较，保留后入队；出队时跳过已被支配的标签，对全部允许后继进行资源检查，尝试返场。队列清空才算完成。负弧成本允许，不能采用Dijkstra式“一次出队便永久定型”。

标签扩展中客户访问集合严格增长，所以零需求/零旅行时间不造成无限路线。提前找到负列、前缀rc非负、直接返场失败，都不能作为停止完整搜索的理由。

## 7. 桶图版：按RouteOpt现有实现适配

### 7.1 保留哪些原版对象和流程

| 原版对象/方法 | DVRP保留的职责 |
| --- | --- |
| all_forward_buckets[i][b]、Bucket.bucket_arcs | 按末端客户i和时间区间b存允许后继；真实资源扩展后再计算目标桶 |
| label_array_in_forward_sense[i][b] | 当前桶标签集；新增标签在桶内做支配 |
| if_exist_extra_labels_in_forward_sense | 每桶待扩展标签；已支配/已扩展者跳过 |
| getTopologicalOrder4OneBin(b) | 本时间区间内可能发生的客户连接，SCC和缩点图拓扑顺序 |
| runLabeling的前向循环 | 时间区间递增 → 区间内SCC → 分量内反复处理新标签 |
| doDominance / checkIfDominated | 插入时桶内支配，扩展前检查同末端更早区间 |
| sortLabelsInBinByRC、rc2_bin / rc2_till_this_bin | 一个区间全部处理完后排序，维护本桶和前缀最小rc |

上述是复制来源及职责映射，不要求公开这些内部对象或保留原版裸指针。多起点、完整访问记忆、double资源和稳定前驱索引是明确的必要适配，不重写无关算法结构。

### 7.2 建桶、允许后继与实际落桶

保留原版统一时间刻度：同一起点上下文中的所有客户使用相同区间边界；按节点×bin存桶，容量仍在标签中检查。区间覆盖所有可行服务完成时间和容差边界；H=0等退化范围使用一个桶。分桶不舍入实际时间。

沿用桶内保存后继客户的结构；保守保留可能连接，只有证明必要资源条件不满足时才排除。源标签按该起点时间播种，返回D作为独立收尾，不让原始0号车场兼任所有起终点。外部S→D单独检查。

扩展后用真实服务完成时间确定目标bin，不把标签固定放入建图时的乐观落桶。例如从[100,110)内t=109出发，旅行3、无等待/服务，到达112应进[110,120)。前缀不能直接返场时仍可扩展后继，不复制与当前截断距离口径不兼容的剪枝。

### 7.3 时间区间与区间内SCC

沿用getTopologicalOrder4OneBin：在区间b中，对可能仍落在b的客户扩展建立依赖图。用区间下界作乐观传播，保守覆盖全部真实同bin扩展；包含所有客户，包括孤立节点，再计算SCC与完整拓扑顺序。

源播种完成后，按bin递增处理；同bin内按SCC拓扑序推进，同一SCC内一直处理新标签直到清空。跨bin扩展只能进入更晚bin；零旅行/服务时间可能停在原bin，不能只扫一遍。D只接收完成路线，不向客户回流。

旧V2提出显式构建论文全局“桶弧＋Phi依赖边”扩展图；现改为原版的一维bin外层顺序＋bin内SCC，不另加通用Phi图。论文的依赖关系用于校验调度完整性，不能把它与RouteOpt的数据结构混为一谈。

### 7.4 桶内/跨桶支配与成本界

沿用doDominance：新标签先与同一末端、同一bin标签比较。扩展前沿用checkIfDominated，检查同末端更早bin。支配判据仍为第6节的资源、rc和完整访问集合条件；较晚bin不可能拥有更早时间，故不用检查。

一个bin中所有SCC处理完后，按rc排序标签列表，更新每个客户本bin最小rc及截至该bin的前缀最小rc。若前缀最小值已大于待检查标签rc，可停止检查这部分更早桶；若排序列表中的rc已过界，可停止该列表扫描。

只使用**已完成更早bin**的定型成本界，不能用当前bin尚会变化的最小值作剪枝依据。成本界只减少支配比较，不是BP节点下界，也不授权删除可行路线。每轮dual改变重置；容差采用保守判定，不能累积误删。

### 7.5 完整性与暂不迁移项

正确性依次检查：桶/后继表覆盖合法扩展；时间资源不减使bin不会倒退；乐观同bin依赖图覆盖真实依赖；SCC内反复处理保证不漏标签；安全支配保留最优见证。有限elementary路径空间完整搜索后，两版应得到相同最小rc，浮点实现另用独立枚举验证。

暂不迁移双向扩展和拼接、ng、cuts、成本弧消除/jump arcs、自适应/二维桶、启发式定价。Jump arcs与成本弧消除的兼容性有关，本次不做该项消除，不因原版循环包含jump_arcs就把它一并启用。当前目标是**原版前向桶图骨架的DVRP适配**，不是完整原版求解配置。

## 8. 结果与下游边界

实际接口类型见[pricing_controller.hpp](../../../../packages_dvrp/application/dvrp/src/pricing/include/pricing_controller.hpp)。每个StartPricingResult保存hasFeasibleRoute、minimumReducedCost和bestRoute；PricingResult另保存负列candidates、上下文标识、统计、耗时和诊断。

Complete意味着所有起点均完成；只有同时无负候选，才给出当前阶段/dual/Phase下容差意义的无负列证据，不等同有理数精确证明或整数方案。TimeLimit、ResourceLimit和Error均清空本轮最小值及候选，不允许调用方消费部分结果。

根模型Phase-I和Phase-II的定价可行域相同。每轮dual改变重建标签、桶和成本界；本版没有图缓存。返回原客户ID和startKey；RMP独立校验路线并写LP，不直接接受标签对象。

## 9. 验证与构建边界

DVRP_BUILD_PRICING_TESTS默认OFF。开启后dvrp_pricing_test编译两版生产源码、动态距离实现及独立测试枚举器，不链接CPLEX；另建dvrp_pricing_property_test，以从头评估子集/排列的独立测试实现加强核对，不调用生产扩展/距离函数或原5客户枚举器。同时启用DVRP_BUILD_RMP_TESTS后另建dvrp_pricing_rmp_test。所有选项关闭时保留原reader/动态构建。

测试枚举器不调用生产扩展或支配，生产pricing不依赖枚举全集。固定stage/phase/dual做三方对照；两版分别驱动测试CG，允许列顺序和迭代数不同，但最终LP与完整集合划分LP一致。

性能统计区分建图与搜索；普通版图指标为0。计数跨起点累计，peakRetainedLabels取单起点最大保留记录数，非进程峰值内存测量。构造预处理不计入price.seconds，不能将该字段标为完整阶段耗时。

两个测试开关均开启时另建dvrp_pricing_instance_test。它读取实际TXT，经DynamicController提取时间0已披露客户；可取前若干客户作为明确标记的子集。对空RMP的Phase-I dual及单客户初始列RMP的Phase-II dual各测试一次，两版使用同一快照；未构建完整路线全集，不将其称作收敛列生成。大实例实验不进入默认CTest耗时回归，仅注册C101已披露客户的2客户子集冒烟。
