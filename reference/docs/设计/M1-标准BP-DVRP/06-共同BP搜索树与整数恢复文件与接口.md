## 1. 本次接通什么

```text
测试调用者（未来才是动态事件循环）
  → DVRP_BpController.solve(StageProblem, BpOptions)
      → 通用BBT：待处理节点、当前节点、有效界记录
      → RootCg.solve(stage, BranchContext, nodeOptions)
          → 已有RMP ↔ 已有普通/桶图pricing
      → selectCandidate / 整数恢复与校验 / makeChildren
  ← BpResult：状态、可选整数见证、上下界及逐节点记录
  → toStageSolution(result)：显式状态转换，不执行车辆
```

`StageProblem`仍是数据快照，不是根节点；新BP控制器负责调度，通用树不认识客户。节点LP服务仍是现有 `DVRP_RootCgController`，虽然名称含Root，它已经支持受限子节点，不再复制CG或重写标签算法。

## 3. 接口、数据及所有权

### 3.1 上层只需调用两个入口

```cpp
// 已实现接口，类型声明集中在 bp_controller.hpp。
BpResult DVRP_BpController::solve(const StageProblem&, const BpOptions&) const;
StageSolution toStageSolution(const BpResult&);
```

`BpOptions(strategy, backend)`必须显式指定RF或专属有向弧，拒绝None；默认阶段总时限60秒、最多10000次节点CG调用。包含现有 `RootCgOptions nodeCg`；后端以 `nodeCg.pricing.backend` 为唯一来源，求解期间固定。节点内部LP/标签/迭代预算继续有效。统一使用nodeCg的绝对/相对gap参数（默认1e-6/1e-8），不再新增第二套隐式阈值。

`BpResult`保存stageId、策略、后端、状态、可选整数见证、可选路线成本下界/上界、加固定成本后的总界、绝对/相对gap、耗时及节点记录。没有见证时上界/gap为空；空路线集合也可能是合法见证，不能用 `routes.empty()` 判断有无解。

整数见证保存原 `StageRoute` 列表、重算路线成本和来源节点/限制；不包含人工变量。`BpNodeRecord`保存节点/父ID、深度、上下文、CG状态、有效界、选择的候选、处理原因及CG迭代记录；消费后释放LP列快照，不给每个已关闭节点保留Solver或完整列池。中断保留当前节点诊断。

### 3.2 树对象与节点LP对象不是一回事

通用 `BBTController<Payload>`管理值节点：ID、可选父ID、深度、路线成本下界及Payload；DVRP的Payload是 `BranchContext`。根ID为0，树内单调分配子ID，并核对Payload的nodeId一致。下一阶段重新创建树与编号空间。

- `startNext`：按下界最小、ID最小取出节点，并保留为active；从队列移除不代表解决。
- `updateActiveBound`：同一节点只收紧有效下界；未求解子节点继承父界，不继承父LP状态。
- `replaceActive`：将父节点替换为两份子限制，原子完成；两份未建立完之前父仍计入未解决集合。
- `closeActive`：由应用说明已证明不可行或提供终结下界；树不自行判断路线整数性。
- `globalLowerBound`：同时考虑队列、active、已终结分区的界及当前上界，规则见第6节。

首次根下界为0，依据是本模型路线成本非负；仅适用于已通过输入检查的阶段。每次solve独立拥有树、上界和记录；节点CG局部拥有并销毁RMP/pricing。输入const引用只在调用期间使用，返回结果为值，不留悬空引用。

### 3.3 整数恢复是无solver的值操作

同一头中声明 `recoverIntegerRoutes(stage, nodeCgResult, selection)` 和 `validateIntegerRoutes(stage, context, routes)`，供控制器与无solver测试调用。前者返回Recovered/NotRecovered/NumericalUnresolved/Error及可选见证；后者独立重算整套路线上界，失败不产生见证。

恢复只消费 `LpConverged` 的Phase-II快照，核对stageId、完整context、modelRevision、零人工量、lambda/列映射和候选来源。调用者不能把中断快照或 `NoFractionalCandidate` 单独当整数证明。原客户ID和startKey不变；pricing内部编号仍由pricing自己转换。

## 4. 一个完整调用例子

输入：原始起点0、三个客户（需求各1、容量2、同在距车场10的位置、时间窗充足），无外部起点、固定成本0；选择RF＋桶图。

1. 新树建立根，调用现有CG，得到成本30的分数解：三条双客户路线各0.5。
2. RF选客户1、2，生成分开/一起两份上下文；树赋不同ID，子节点初始继承根有效下界。
3. 每个子节点重新运行Phase-I/II，允许pricing补上被初始单列遗漏的合法路线。不能因为初始真实列不足就剪枝。
4. 恢复如 `[1,2]` 和 `[3]` 的整数选择，重算成本40；满足覆盖、容量、时间窗和RF限制后更新上界。
5. 当前节点及其余分支均被有效解决/剪枝后，返回容差内Optimal、整数路线及数值上下界；下界可能因浮点余量略低于40，不能直接写成严格40。
6. `toStageSolution`生成已有格式的整数方案；本次测试不自动推进动态事件。更换为专属有向弧时，子问题和节点数可不同，完成后的最优值应相同。

## 5. 整数恢复与校验

每个收敛节点先调用 `selectCandidate` 检查完整快照；随后尝试近整数lambda提出的路线集合。数值阈值只帮助提案，选择后必须用整数计数验证所有行恰好一次。若未恢复且有分数候选，正常分支；仅在无候选时启动下述结构恢复。

RF把列映射为“带类型客户/外部行”的覆盖集合。同一集合的正值列归一块，块必须不重叠且覆盖全部行；按重算成本、startKey及客户序列确定性地选最小列。外部空列的集合是对应外部行，原始列不增加起点行。

依据：精确算术下，正列含u、v则共同流量为正；无分数RF候选使它等于1，故任何含u的正列都含v。于是正值列的覆盖集合相同或不交，每块权重和为1，选最便宜列不增加LP成本。完整推导见[设计05第7节](05-双策略分支与受限列生成文件与接口.md#7-子节点恢复下界与无候选)。

弧模式按 `(startKey, from, to)` 核对全部连接。精确整数流量和客户覆盖使每客户唯一入/出弧，正列只能对应相同或客户不交的完整路径；从原始Source可有多条不同出发路线，外部Source恰有一条，直接返场单独保留。仅从现有正值列恢复/去重完整序列并与这些连接核对，不用几条零散弧拼出未经校验的新路线。

结构恢复保留所有严格正lambda列参与检查，不默默丢掉极小正列后声称证明成立；轻微负值、近0/1仅能提出候选。数值尘埃导致不满足块/连接条件时可以返回未解决，不能靠放宽容差获得“证明”。近整数提案即使绕开结构问题，也必须独立校验并与有效下界比较。

`validateIntegerRoutes`用原ID映射复核每条路线的起点、elementarity和分支限制，按 `routeOptDistance` 从起点时间/剩余容量传播、允许等待并立即离站、检查H；整组路线再做客户和外部行的精确一次覆盖。重算成本，不信任列缓存或LP目标；固定成本只加一次。此函数不调用动态 `acceptSolution`，因此不修改车辆状态。

恢复失败且无候选→NumericalUnresolved；快照错配/非法ID→Error。恢复成功只形成上界：节点见证成本与有效下界不闭合时，若仍有候选则继续分支，否则返回NumericalUnresolved。候选与既有决定重复、不产生真子问题时停止报错，不能空转。

## 6. 全局界、剪枝与容差

记L为路线成本下界、U为已验证最优见证的路线成本；统一 `tol(U)=absTol+relTol*max(1,abs(U))`。阶段固定成本不进入这个比较尺度。节点CG终止仍沿用既有设计04，不把其小负rc或Phase-I目标重新解释为整数证明。

节点有效L取继承界与该节点已闭合Phase-II保守界的较大者；证书须核对context、版本、Phase和快照。中断CG不新增剪枝依据，只保留原先有效的继承界。已证明Phase-I不可行的分区视作下界正无穷。

有限U存在时，L≥U−tol(U)可容差剪枝；节点获得自身整数见证且其成本与L闭合时亦可结束。该节点见证若低于本节点有效L，先检查数值一致性并报告异常，不简单截断差值。所有关闭动作须记录理由及终结下界。

树维护队列界、active界，以及所有未分裂的已终结分区界的最小值 `closedMin`（不可行分区不参与有限最小值）。父分区被子分区替换时不永久保留较弱父界。全局界为：

```text
G = min(U（若存在）, 队列各界, active界（若存在）, closedMin（若存在）)
```

这些分区共同覆盖原整数可行域，因此G仍为有效下界；终结记录使容差剪枝不会在清空队列后伪造G=U。早停时active仍计入；没有已求节点界但有合法未处理根时仍有平凡界0。全部分区证明不可行时报告Infeasible，不用0作为“不可行最优值”。

只有验证见证存在且U−G在显式容差内，或完整分区处理证明满足同一标准，才返回Optimal。输出实际gap与容差口径，不将小正gap改成0；缺少界则gap为空。保留现有浮点求解/定价局限，不称为有理数证书。

## 7. 状态、时间与统计

BP状态为 `Optimal / Infeasible / TimeLimit / NodeLimit / ResourceLimit / IterationLimit / NumericalUnresolved / Error`。除合法Optimal/Infeasible外都表示未完成；不因有上界就降格成可执行的Feasible。

| BP结果 | `toStageSolution` 映射 |
| --- | --- |
| Optimal且有已验证见证 | `SolveStatus::Optimal`＋路线 |
| Infeasible且无见证 | `SolveStatus::Infeasible` |
| TimeLimit有/无见证 | 对应 `TimeLimitWithSolution / TimeLimitWithoutSolution`，保留诊断路线，不执行 |
| 节点/资源/迭代上限、数值未解决或Error | `SolveStatus::Error`，message保留原BP原因及诊断路线；完整类型仍在BpResult |

状态与见证矛盾时拒绝转换为成功。转换放在integer_recovery.cpp，不修改既有动态枚举；未来动态接入会按现有停止分支处理，当前不自动调用acceptSolution。

整次solve用steady_clock计时，每次CG时限取阶段剩余与nodeCg单次上限的较小值。`maxNodes`计实际启动的节点CG（含根），纯界剪枝不耗一次CG；仍记录创建/处理/分裂/剪枝数。任何子组件超时/限制立即停止阶段，不尝试另一个后端或兄弟节点掩盖未完成。

最终化与对象释放后再检查总时间；晚于截止不能仍返回Optimal。保留已验证见证和已有界，但不消费超时CG的部分定价候选。不承诺构造/不可中断API硬实时退出；内存分配失败尽力返回ResourceLimit，不能保证真实OOM下还能生成完整日志。

新增CG统计字段在pricing返回后、任何时限退出前赋值，区分未调用与零标签；树对调用次数/生成扩展数求和，对峰值取max，原样保留未完成调用的诊断统计。统计不作为最优证书，也不表示整个进程内存上限。

## 8. 构建隔离与验证边界

新增默认OFF的 `DVRP_BUILD_BP_TESTS`（无solver）及 `DVRP_BUILD_BP_SOLVER_TESTS`（CPLEX），均要求BUILD_TESTING；后者不要求用户把全部历史测试开关打开。默认reader仍无solver依赖，生产文件不链接test枚举/MIP；oracle仅在测试目标中链接。

无solver测试使用通用树、整数恢复和转换函数：同下界不同ID不丢节点、active保留、父子替换、终结界记账、无上界/空见证、RF同覆盖不同顺序、外部空列/绑定、有向首尾连接、微小正列、覆盖冲突、版本错配及不同未完成状态。确定性模拟验证停止政策，不能声称模拟等于真实solver超时。

CPLEX测试运行真实BP：手算LP30/IP40、根即整数、空阶段/仅外部返回、证明不可行、多层分支、固定成本、非连续ID、多次求解隔离；固定种子至少100个2—5客户且0—3外部起点阶段，四种组合对照完整集合划分MIP，逐路线独立复核。保留原对照器上限，不把枚举供列给生产CG。

另核对真实0总预算、节点/迭代/标签上限；有解/无解停止与错误映射用确定性状态用例补齐，明确哪些是真实观测。节点数和不同最优路线不要求相同；性能比较记录同阶段、同预算与硬件环境，不承诺100客户通过。

上述接口已落地；测试命令、实际通过数量、真实TXT子集及静态回归结果统一见模块说明，不在设计中复制第二套记录。C204不带-u；R204历史未完成风险单独报告。下一步动态事件/CLI接入另行确认，不随本模块自动扩展。
