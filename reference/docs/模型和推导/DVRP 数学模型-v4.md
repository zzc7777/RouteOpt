## 1. 问题描述

本文研究一个由新增顾客请求触发的动态带时间窗车辆路径问题（Dynamic Vehicle Routing Problem with Time Windows，DVRPTW）。本问题的具体业务为取货：车辆空载从原始车场出发，在顾客点收取货物，并最终将所收货物运回原始车场。所有车辆的标准容量均为 $Q$。

在作业开始前，根据当时已知的顾客信息制定初始服务方案。随着车辆执行任务，新的顾客请求可能陆续出现，每次接收到新增请求时，均触发一次路径重优化。顾客请求一经接收，其位置、需求量、服务时间和时间窗均视为已知且保持不变。

本问题不预测未来可能出现的顾客，也不假设未来请求的到达时间、位置或需求量服从某种已知的概率分布。每次重优化仅依据当前已经获得的顾客信息与车辆状态进行规划。已经完成的服务、已经行驶的路径以及当前已承诺的任务保持不变，仅调整后续尚未承诺的服务任务。本文忽略重优化计算及调度指令传输所需的时间。

车辆到达顾客点后，若时间窗已经开启，则开始服务；若提前到达，则等待至时间窗开启后开始服务。完成服务后，车辆立即驶向下一顾客；若无后续顾客，则立即返回原始车场。车辆在行驶途中不得改变当前目的地。每辆车在本作业期内至多执行一趟任务，所收取的货物由该车运回原始车场，返场后不再重新出车。

所有启用车辆均须在作业期结束时刻 $H$ 之前或恰好在 $H$ 返回原始车场；采用 Solomon 实例时，$H$ 取车场数据行的 `DUE_DATE`。该上限同时适用于原始车场出发路径、外部车场接续路径（含直接返场路径）以及已经固定的返场行程。

设当前动态调整时刻为 $\tau$，根据车辆状态及同时事件的发生情况，分别按以下方式处理：

1. **正在前往顾客的车辆。**
   车辆继续驶向当前目的地，并完成该顾客的服务后，再执行调整后的后续路径。该顾客属于车辆当前已承诺的任务，其车辆分配保持不变。

2. **已到达顾客点、正在等待时间窗开启的车辆。**
   车辆继续等待至时间窗开启，并完成该顾客的服务后，再执行调整后的后续路径。该顾客属于车辆当前已承诺的任务，其车辆分配保持不变。

3. **正在为顾客服务的车辆。**
   车辆继续完成当前服务，不得中断服务或将该顾客转交其他车辆。服务完成后，车辆执行调整后的后续路径。

4. **正在返回原始车场的车辆。**
   车辆继续沿既定返场行程返回原始车场，不得在返场途中改向其他顾客。其剩余行程保持不变，不参与本次服务任务的重新分配，剩余行驶成本作为固定成本计入。

5. **尚未出发、在原始车场等待的车辆。**
   这些车辆可以从原始车场出发，参与后续服务。选中路径的车辆统一按允许的最早时刻 $\tau$ 实际发车，出发时为空载状态，可用装载容量为 $Q$。允许提前到达顾客处等待，不为避免等待而主动推迟发车。

6. **已完成任务并返回原始车场的车辆。**
   这些车辆已结束本作业期内的任务，不再参与后续服务。

7. **新增请求到达与车辆完成顾客服务同时发生的情形。**
   若新增请求恰好在车辆完成顾客服务的时刻到达，则先更新服务完成状态，在该顾客位置生成本阶段外部起点，再调整车辆的后续路径，随后立即出发。刚完成服务的顾客不再参与本次顾客分配；新阶段的外部起点仍对应原车辆，不新增车辆，也不恢复其已占用容量。

将第 1—3 类及第 7 类情形中的车辆记为执行中车辆，其集合为 $K^E$。对每辆执行中车辆 $k$，将其完成当前顾客服务的地点复制为车辆专属的虚拟起点，称为外部车场，记为 $O^k$。后续路径的出发时刻记为 $T^k$，对应的剩余装载容量记为 $R^k$。

其中，第 1—3 类车辆的 $T^k$ 为当前已承诺顾客的服务完成时刻，第 7 类车辆的 $T^k=\tau$。$R^k$ 等于标准容量 $Q$ 减去车辆在 $T^k$ 时刻的实际载货量。外部车场仅用于表示车辆后续路径的初始状态，其需求量和服务时间均为零，对应顾客的服务不在后续路径中重复安排。

每次重优化的服务对象为截至时刻 $\tau$ 已知、尚未完成服务且不属于当前已承诺任务的顾客，包括原计划中的剩余顾客和新增顾客。每个顾客必须由一辆车服务且仅服务一次，需求不可拆分。车辆承担的后续需求总量不得超过其剩余装载容量，且必须在各顾客的硬时间窗内开始服务。

在单次重优化中，执行中车辆的后续路径从各自的外部车场出发，每个外部车场仅对应一辆指定的执行中车辆；待命车辆从原始车场出发，原始车场可供启用的待命车辆数量不受限制。所有参与服务的车辆最终均返回原始车场。因此，该子问题可以表述为具有车辆专属起点和共同终点的多车场带时间窗车辆路径问题。外部车场是由车辆执行状态形成的虚拟起点，系统中的真实车场仍只有一个。

每次调整需要确定待规划顾客的车辆分配、待命车辆的启用情况，以及各辆车后续访问顾客的顺序。在满足顾客唯一服务、车辆容量、硬时间窗、已承诺任务保持不变和统一返场等要求的条件下，以最小化当前决策时刻之后的车辆总行驶成本为目标。后续再次出现新增请求时，更新顾客信息与车辆状态，并重复上述重优化过程。

### RouteOpt 实例的数值约定

本项目首期采用当前 RouteOpt VRPTW 的数值口径：欧氏距离经 `transformCost` 按一位小数向下截断（带原实现的数值容差），用该弧距离同时作为行驶成本和旅行时间，即 $c_{ij}=t_{ij}$。一般模型仍分别保留成本与时间符号。客户时间窗和返场上限的可行性比较沿用 RouteOpt 容差，不将客户披露时间额外截断到一位小数。

动态执行与阶段求解使用同一组弧成本和时间。在匀速执行的约定下，事件切分一条弧时按已完成比例结算实际距离，不对每个部分行程再次取整；整条弧执行完成后的累计值应等于该弧成本。等待和服务只消耗时间，不增加行驶成本。


## 2. 集合划分模型

针对动态调整时刻 $\tau$ 对应的重优化子问题，建立集合划分模型。模型通过选择可行路径确定后续服务安排，容量、时间窗、出发状态和统一返场等要求均包含在可行路径的定义中。

由于待命车辆同质且数量不受限制，不对其逐辆编号。每条被选中的原始车场出发路径由一辆待命车辆执行。


### 2.1 集合与参数

以下集合和车辆状态均对应当前决策时刻 $\tau$，为简化记号，省略其对 $\tau$ 的显式依赖。在每次重优化子问题中，将待规划顾客重新编号为 $N=\{1,\ldots,n\}$。

| 符号 | 含义 |
| --- | --- |
| $N$ | 当前已知、尚未完成服务且不属于已承诺任务的待规划顾客集合 |
| $n$ | 待规划顾客数量，即 $n=\lvert N\rvert$ |
| $K^E$ | 从顾客点接续执行调整后路径的执行中车辆集合 |
| $O$ | 原始车场的出发节点 |
| $n+1$ | 原始车场的返回节点，与 $O$ 对应同一物理位置 |
| $O^k$ | 执行中车辆 $k$ 专属的外部车场，$k\in K^E$ |
| $O^E$ | 外部车场集合，$O^E=\{O^k:k\in K^E\}$ |
| $q_i$ | 顾客 $i$ 的需求量，即需要从该顾客处收取的货物数量，$i\in N$ |
| $[a_i,b_i]$ | 顾客 $i$ 的服务开始时间窗，$i\in N$ |
| $s_i$ | 顾客 $i$ 的服务时间，$i\in N$ |
| $Q$ | 车辆的标准装载容量 |
| $H$ | 所有启用车辆的最晚返场时刻；Solomon 车场行的 `DUE_DATE` |
| $T^k$ | 执行中车辆 $k$ 从外部车场开始执行后续路径的时刻 |
| $R^k$ | 执行中车辆 $k$ 在时刻 $T^k$ 的剩余装载容量，$0\le R^k\le Q$ |
| $c_{ij}$ | 从节点 $i$ 到节点 $j$ 的行驶成本 |
| $t_{ij}$ | 从节点 $i$ 到节点 $j$ 的行驶时间 |
| $C_\tau^{\mathrm{fix}}$ | 时刻 $\tau$ 之后不可调整部分的固定行驶成本 |

节点集合为：

$$
V=N\cup O^E\cup\{O,n+1\}.
$$

问题定义在有向图 $G=(V,A)$ 上，其中 $A$ 为允许行驶的弧集合。各车场节点在路径模型中的需求量和服务时间均设为零。

固定成本 $C_\tau^{\mathrm{fix}}$ 包括：执行中车辆完成当前已承诺任务所需的剩余行驶成本，以及正在返场车辆的剩余返场成本。时刻 $\tau$ 之前已经发生的行驶成本不计入本次目标。


### 2.2 可行路径集合

定义两类可行路径集合：

- $\Omega_k^E$：执行中车辆 $k\in K^E$ 的所有可行后续路径集合；
- $\Omega^O$：一辆待命车辆从原始车场出发的所有可行服务路径集合。

每条可行路径均包含顾客访问顺序及相应的可行时间安排，并满足以下共同要求：

- 路径内部仅包含集合 $N$ 中的顾客，同一顾客在一条路径中至多出现一次；
- 每个被访问顾客的需求由该路径对应的车辆完整服务；
- 路径上顾客的需求总量不超过车辆在路径起点的可用装载容量；
- 满足行驶时间、服务时间和顾客硬时间窗要求，并遵循前述等待与服务完成后立即出发的规则；
- 最终到达原始车场的返回节点 $n+1$，且到达时刻不晚于 $H$。

两类路径的起点及初始状态分别为：

| 项目 | 执行中车辆路径 $r\in\Omega_k^E$ | 待命车辆路径 $p\in\Omega^O$ |
| --- | --- | --- |
| 出发节点 | 车辆专属外部车场 $O^k$ | 原始车场 $O$ |
| 出发时刻 | $T^k$ | 允许的最早时刻 $\tau$ |
| 可继续服务的需求总量上限 | $R^k$ | $Q$ |
| 顾客访问要求 | 可以不再访问顾客，直接返回 $n+1$ | 至少访问一个顾客 |

其中，$\Omega_k^E$ 包含直接由 $O^k$ 返回 $n+1$ 的路径，以允许执行中车辆在完成当前已承诺任务后直接返场。


### 2.3 路径参数与决策变量

**路径参数**

| 符号         | 含义                                           |
| ---------- | -------------------------------------------- |
| $c_{kr}^E$ | 执行中车辆 $k$ 采用路径 $r\in\Omega_k^E$ 的行驶成本        |
| $c_p^O$    | 待命车辆采用路径 $p\in\Omega^O$ 的行驶成本                |
| $e_{ir}^k$ | 若路径 $r\in\Omega_k^E$ 服务顾客 $i$，则为 $1$；否则为 $0$ |
| $o_{ip}$   | 若路径 $p\in\Omega^O$ 服务顾客 $i$，则为 $1$；否则为 $0$   |

路径成本为沿途各弧行驶成本之和：

$$
c_{kr}^E=\sum_{(i,j)\in r}c_{ij},
\qquad
c_p^O=\sum_{(i,j)\in p}c_{ij}.
$$

**决策变量**

| 符号 | 含义 |
| --- | --- |
| $\lambda_{kr}^E$ | 若执行中车辆 $k$ 选择路径 $r\in\Omega_k^E$，则为 $1$；否则为 $0$ |
| $\lambda_p^O$ | 若选择路径 $p\in\Omega^O$ 并启用一辆待命车辆执行，则为 $1$；否则为 $0$ |


### 2.4 目标函数与约束

**目标函数：最小化当前决策时刻之后的总行驶成本。**

$$
\min Z_\tau
=
C_\tau^{\mathrm{fix}}
+
\sum_{k\in K^E}\sum_{r\in\Omega_k^E}
c_{kr}^E\lambda_{kr}^E
+
\sum_{p\in\Omega^O}
c_p^O\lambda_p^O.
$$

其中，$C_\tau^{\mathrm{fix}}$ 为常数，实际求解时可以省略，不影响最优路径选择。

**（1）顾客唯一服务约束**

每个待规划顾客必须由一条被选中的路径服务且仅服务一次：

$$
\sum_{k\in K^E}\sum_{r\in\Omega_k^E}
e_{ir}^k\lambda_{kr}^E
+
\sum_{p\in\Omega^O}
o_{ip}\lambda_p^O
=1,
\qquad \forall i\in N.
$$

**（2）执行中车辆路径选择约束**

每辆执行中车辆必须选择一条后续路径，该路径可以继续服务顾客，也可以直接返回原始车场：

$$
\sum_{r\in\Omega_k^E}\lambda_{kr}^E=1,
\qquad \forall k\in K^E.
$$

**（3）变量取值约束**

$$
\lambda_{kr}^E\in\{0,1\},
\qquad
\forall k\in K^E,\ r\in\Omega_k^E.
$$

$$
\lambda_p^O\in\{0,1\},
\qquad
\forall p\in\Omega^O.
$$

每条被选中的原始车场路径对应一辆被启用的待命车辆，因此启用的待命车辆数为：

$$
\sum_{p\in\Omega^O}\lambda_p^O.
$$

由于待命车辆数量不受限制，无需另设车辆数量约束。容量、时间窗、车辆专属起点、出发时刻和统一返场等要求由可行路径集合保证；正在固定返场的车辆不设置路径选择变量。
